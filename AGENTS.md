### 401 flood root cause + fix (DONE — client stale-token recovery + server 502 distinction)
- **Root cause was NOT the API**: the server correctly 401s when no/garbage token is sent; Supabase REST DNS works. The browser was sending an EXPIRED/stale access token (supabase-js rotates it, but a burst of parallel calls can all observe a just-expired token, and a reload can resume with a token that expired while closed).
- **Client fix `src/context/AppContext.jsx`**: `callApexApi` now, on `status===401 && hadBearer && !networkError`, calls module-level deduped `ensureFreshSessionToken()` (guard: skip if a successful refresh happened <5s ago; single in-flight `refreshSession()` shared by the burst — GoTrue refresh tokens are single-use), then replays the request once with the fresh token. If refresh fails → `supabase.auth.signOut()` (lands on login instead of 401 spam) and returns `{ok:false, status:401, authExpired:true}`. `onAuthStateChange` gained a `TOKEN_REFRESHED` arm that calls `setSession(currentSession)` so context tokens stay fresh. Converted the session helpers (registerDeviceSession / fetchActiveDevices / revokeDevice / touchDeviceSession) and `DailyChallengeWidget.jsx` (both fetches + added `callApexApi` to dep arrays) onto `callApexApi`. Raw `/api` fetches remain only in Reviews (`/api/feedback`), Activate (`/api/initiate-payment`), PaymentVerify (`/api/verify-payment`) — non-critical.
- **Server fix `api/_utils.js`**: `getUserFromRequest` throws `{code:'AUTH_SERVICE_UNAVAILABLE'}` on a GoTrue *network* error; `getUserAndVerifySession` returns `{user, revoked, sessionId, upstreamError}`; `authorizeRequest` returns **502 `{error:'AUTH_SERVICE_UNAVAILABLE'}`** on upstream failure instead of a bogus 401 (401 is now reserved for genuinely invalid/missing tokens). Verified live: `GET /api/quota/course-status` with no token → 401 `Unauthorized` (correct).
- **serve-api.mjs note**: handlers are dynamically imported with `?t=${Date.now()}` per request (hot); `_utils.js` is a static import in that chain — safest to `taskkill` the serve-api child before final verification (dev.mjs auto-restarts it).
